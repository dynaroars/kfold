=== PROBLEM P13: Reverse lookup and explanation: which CONFIG builds object or driver X, and why is it missing from my build
who: Driver maintainers, patch authors, distro/embedded configurers, ordinary kernel builders, reviewers
strength: Moderate. About 23 claims, mostly anecdotes from independent forums and lists over 2011-2025. Few are recent (192, 147, 24). One survey statistic (20% of respondents) via a 2020 paper. Counter: a tool (kernelconfig.io) answers symbol-level lookups; HN says mainstream users do not want to tailor.
existing: menuconfig '/' search, kernelconfig.io, LKDDB (cateee.net), grep, localmodconfig, ConfigFix (research), merge_config.sh warnings, Yocto audit.
gap: An exact Makefile-derived boolean condition for the object plus an explanation chain against a given .config (the why command), including the unmet-dependency step. Kbuild-only explanation leaves the Kconfig step unresolved.
fit: partial - why OBJ answers the Kbuild half precisely. The dominant user pain (292, 93, 144) is at the Kconfig dependency step, so full value depends on integrating the Kconfig model, which kfold does only for config-for.

[23] (pain_point/anecdote, 2025-06-24) Commenter on the defconfig article: it has become easy to build a kernel that does not work because of one wrongly disabled option, and distros spend large effort on it. Users cannot easily see what a config option gates.
    quote: "it has become increasingly easy to build a non-working kernel due to a stupidly disabled option"
    source: Default kernel configuration (comment thread on 'Who are kernel defconfigs for?') | wtarreau (commenter) | LWN.net | https://lwn.net/Articles/1026717/
    candidate_problem: why: explain which option/condition keeps a needed object out of the build ('why is driver X.o not in my kernel')

[24] (pain_point/anecdote, 2025-06-24) Corbet's report of the defconfig discussion: configuring is not fun, and a missing driver means a non-working kernel. Linus Torvalds called kernel config the nastiest part of building a local kernel. Developers are asked to test on x86 defconfigs, which are rarely used to build kernels that actually run, so the standard build-test configs diverge from real use.
    quote: "Failing to enable a needed driver will result in a non-working kernel."
    source: Who are kernel defconfigs for? | Jonathan Corbet (Torvalds quoted in comments: "the kernel config is likely the nastiest part of building a local kernel") | LWN.net | https://lwn.net/Articles/1026337/
    candidate_problem: config-for / blindspots: defconfig-based build testing misses objects real users enable

[89] (need/anecdote, 2020-12-30) Open problem stated (ConfigFix, ICSE SEIP 2021): Linux users struggle with kernel configuration and resolving configuration conflicts because the kernel lacks automated support; research tooling mostly did not make it into the kernel.     quote: "Linux users still struggle with kernel configuration and resolving configuration conflicts, since the kernel largely lacks automated support."

[140] (pain_point/anecdote, 2013-02-21) Forum users cannot map a module/.ko name to the menuconfig option that builds it. Arch BBS thread 'Finding modules in menuconfig' (2013-02-21, 12 replies): OP could not find options for cdrom.ko, i2c-algo-bit.ko, libata.ko, usbcore.ko. Answers: search in menuconfig, grep .config with the uppercase module name, use the cateee.net LKDDB, or run make localmodconfig. No reply mentions grepping Kbuild Makefiles. Module name and CONFIG symbol often differ (i2c-algo-bit is I2C_ALGOBIT).
    quote: "just can't find them anywhere."
    source: Finding modules in menuconfig | junex (OP) | Arch Linux forums (Kernel & Hardware) | https://bbs.archlinux.org/viewtopic.php?id=158476
    candidate_problem: Reverse lookup from object/module to the Kconfig condition that builds it ('which CONFIG enables file X'), answered from Kbuild rather than from folklore.

[141] (pain_point/anecdote, 2017-04-27) make localmodconfig only keeps modules loaded at the time it runs, so a custom kernel built from it silently lacks drivers for hardware or filesystems not in use at that moment.     quote: "Using LMC only works if the needed modules are loaded before you start compiling."
    source: [solved] missing modules with custom kernel & localmodconfig | graysky (Arch wiki maintainer) replying to OP | Arch Linux forums (Kernel & Hardware) | https://bbs.archlinux.org/viewtopic.php?id=225599
