=== PROBLEM P10: CVE applicability: is the file touched by this fix built in my configuration
who: Distro and embedded maintainers, CIP and LTS operators, product security teams (EU CRA), SBOM/VEX producers, Yocto users
strength: Strongest new cluster. About 29 claims, independent and recent (2024-2026): kernel-docs policy, LKML maintainers' quotes, LWN, Siemens/CIP slides with numbers, three conference talks (LPC, OSS Europe, KubeCon India), a BeagleBoard forum and an arXiv/ISSTA paper. Compliance-driven (CRA) and funded. Claim 20's '2,000 per month' conflicts with about 60 per week.
existing: CIP kernel-cve-triage (Kmax-formula based; checks check_introduced_by_file_compiled), cvehound (Kbuild-derived config), PatchLens (FSE 2026, patch-level conditions), KCVEPruner (function-level), Yocto cve-check and SPDX provenance, compile_commands.json.
gap: Fast, reusable per-object conditions (not per-revision expensive Kmax runs), applied to fix-commit file lists and evaluated against a .config, emitting VEX justifications. Header and function-level granularity and runtime state are not covered. kernel-cve-triage's derivation method is unknown from the claims.
fit: object-selection - File-level 'built or not under .config' is the question kfold answers, and the demand evidence is the strongest and the only compliance-driven one. Caveat: closest competitors (Kmax-based kernel-cve-triage, cvehound, PatchLens) already target it, and kfold stops at file level.

[123] (existing_tool/tool, 2026-06-24) PatchLens (FSE 2026, arXiv 2606.25863, DOI 10.1145/3808126) is a recent static technique that recovers Vulnerability Impact Conditions: Boolean predicates over config options for the variants containing a flaw. It matches patch hunks to source-level presence conditions and analyzes the build system, without compiling variants. It was evaluated on 1,192 Linux, 289 FFmpeg and 100 PHP patches, with an average of 1.84 variables per predicate for Linux. It says CVE text rarely names the required options (about 1% recall) and proposes CI triage and test selection. It overlaps with kfold's idea of per-object conditions, applied to security patches. Header-file impact is future work, and the FSE abstract numbers differ slightly (1,193/290/99, 2.09 variables).
    quote: "a Boolean predicate over configuration options that denotes all variants that contained the original flaw"
    source: Automated Detection of Configuration-Specific Security Vulnerabilities via Patch Analysis | de Sant'Anna Paixao, Santos, da Mota Silveira Neto, Menasche, Figueiredo, de Almeida | FSE 2026 / arXiv. FSE page: https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/49/Automated-Detection-of-Configuration-Specific-Security-Vulnerabilities-via-Patch-Anal. A related SBES 2026 tool paper exists at https://cbsoft.sbc.org.br/2026/data/papers/sbes/Patchlens%20A%20Static%20Analysis%20Tool%20for%20Variant-Aware%20Change%20Impact%20Analysis%20in%20Configurable%20Systems.pdf, but its text was unreadable and it is cited only from a search snippet. | https://arxiv.org/abs/2606.25863
