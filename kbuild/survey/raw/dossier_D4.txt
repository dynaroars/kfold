=== PROBLEM P5: Blind spots: objects that no standard or CI configuration ever builds
who: Subsystem maintainers (esp. drivers, SoC, media), CI operators, fuzzer operators, linux-next integrators, kernel researchers
strength: Strongest cluster. About 34 claims. It has independent recent anecdotes (Hovold patches accepted by multiple maintainers), policy (COMPILE_TEST docs), statistics (6.16 has 32,468 Kconfig options; the 0-day report shows 19 tested, 125 skipped), and principal-maintainer statements. Caveats: Hovold's cases were found manually and fixed, so the effect size across the tree is unmeasured. Torvalds's quotes came through a summarizer (57).
existing: COMPILE_TEST convention, allmodconfig/allyesconfig, 0-day randconfigs, Arnd Bergmann's private randconfig loop, KernelCI's 220+ configs. No tool reports unbuilt objects.
gap: A sound per-object report of objects whose condition no given config set satisfies, grouped by MAINTAINERS entry, so owners can add COMPILE_TEST or a CI config. It must account for arch (11% of patches need cross-compilation) and for intentional dead code (199).
fit: object-selection - The blindspots command is built for this. Per-object conditions give a sound coverage denominator that sampling cannot. Caveat: in the 2025 case k3-socinfo the root cause was Kconfig-spec, though the symptom is visible at object level.
