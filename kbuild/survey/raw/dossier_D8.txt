=== PROBLEM P9: Distro, Android and embedded config maintenance (H8)
who: Distro kernel maintainers (Debian, Fedora/RHEL, Ubuntu), Android OEMs/vendors, ChromeOS, Yocto/OpenWrt integrators
strength: Moderate. About 25 claims from independent documentation and lists. Mostly docs/process descriptions, not pain statements. Many are old (2011-2018). The 2012 LWN thread is the only direct pain statement. Pain is focused on Kconfig/fragment mechanics, not Kbuild object selection.
existing: merge_config.sh, diffconfig, kernel_configcheck/config audit (Yocto), check-configs.pl (Fedora), VTS/compatibility-matrix check (Android), kconfigeditor2 (Debian).
gap: Predict, for a fragment or option change, which objects are added or dropped, and why a requested option or driver did not take effect. Generate minimal fragments from needed objects. Most of the pain is in the Kconfig layer.
fit: partial - Object-delta views help reviewers. The failure points the claims describe (dropped options, dependency chains) are Kconfig-resolution problems that require the Kconfig model beyond Kbuild conditions, and no distro maintainer here asks for object-level output.

--- supporting claims
[44] (workflow_practice/anecdote, 2012-07-18) Distribution configs (2012, older): Torvalds wanted every option in a distro config to carry a comment saying why it is needed. Ben Hutchings said he sometimes does not know what depends on an option, and a Fedora maintainer was blindsided by requirements. Option-to-object dependency knowledge is missing for configurers. Foundational, pre-2023.
    quote: "doesn't mean I know what's using or depending on it now."
    source: Kernel configuration for distributions | Jake Edge (Ben Hutchings quoted) | LWN.net | https://lwn.net/Articles/507239/
    candidate_problem: why: which objects does an option gate? supports distro config minimization

[69] (pain_point/anecdote, 2025-12-11) LPC 2025 Build Systems MC, 'Debian Official Debug Kernel for All?' (Kim, Jin): developers build their own debug kernels, causing inconsistent reproduction and blocking Debian kernels from use with syzbot; Debian team is cautious because extra flavors raise build time, archive storage and mirror traffic; a 'minimal debug configuration' for syzbot/security auditing is an open question. Distro config policy is hand-negotiated.
    quote: "an officially supported, sanitizer-enabled kernel image is not yet available"
    source: Debian Official Debug Kernel for All? | Yunseong Kim (Ericsson), seonghee jin (Georgia Tech) | Linux Plumbers Conference 2025, Build Systems MC | https://lpc.events/event/19/contributions/2030/
    candidate_problem: Distro maintainers weighing config flavors need to know which objects a flavor adds or drops (config-delta impact analysis); page names no specific CONFIG symbols.

[70] (pain_point/policy, 2026 (current docs)) Android GKI FAQ: devices use a config fragment on top of gki_defconfig to build vendor modules, and 'there's no way to avoid some manual examination of configuration options'; scripts/diffconfig is the suggested tool; mismatched ABIs between GKI kernel and module configuration are an 'implicit module config dependency'. Shows vendor/OEM config reconciliation is manual.
    quote: "There's no way to avoid some manual examination of configuration options to optimize the fragment."
    source: Android kernel frequently asked questions | Android Open Source Project | source.android.com (GKI documentation) | https://source.android.com/docs/core/architecture/kernel/gki-faq
    candidate_problem: Fragment/config delta reasoning: which objects change when a vendor fragment is applied over gki_defconfig (build-condition diff instead of textual diffconfig).

[71] (pain_point/anecdote, 2026-05-29) Embedded Recipes 2026 (Yocto workshop) talk 'Config Fragments: Cure or Curse?' (David Heidelberg, 29 May 2026): embedded/mobile devices often rely on device-specific configuration fragments maintained out of tree; even a close-to-mainline kernel can need a bespoke fragment to boot; mainline kernels with similar support frequently yield partly working hardware.
    quote: "they often rely on device-specific configuration fragments maintained out-of-tree"
    source: Config Fragments: Cure or Curse? | David Heidelberg | Embedded Recipes 2026 (Yocto Project Workshop) | https://pretalx.com/yocto-embedded-recipes-2026/talk/39YTU9/
    candidate_problem: Embedded configurers lack a way to tell which objects (drivers) a fragment must enable for a board; condition model could compute minimal fragments (config-for generalized to boards). Abstract only; the talk body was not seen.

[72] (workflow_practice/anecdote, 2023-11-14) LPC 2023 Build Systems MC 'kernel: build system outputs and workflows (and how to balance them)' (Bruce Ashfield, AMD): how the kernel is used (UAPI headers, LTS/-stable vs bleeding edge, testing, supported versions) impacts how it is configured, built, deployed; session covers OpenEmbedded/Yocto kernel integration pain points. Config handled via fragments in Yocto; no coverage tooling mentioned.
    quote: "impact how the kernel is configured, built, deployed and the outputs consumed"
    source: kernel: build system outputs and workflows (and how to balance them) | Bruce Ashfield (AMD) | Linux Plumbers Conference 2023, Build Systems MC | https://lpc.events/event/17/contributions/1640/
    candidate_problem: Embedded build-system integrators carry kernel config fragments per product; no per-object impact analysis offered.

[144] (pain_point/anecdote, 2011-09-01) Driver 'does not build' because of unmet Kconfig dependencies that the user did not know about. Yocto list 2011: reporter could not get e100 to build; diagnosis was missing NET_PCI/MII; a maintainer said a warning should appear when a fragment option does not reach .config, and the reporter did not confirm that it did.
    quote: "Yes, the problem was due to missing dependent options.."
    source: [yocto] e100 driver does not build | Rahul Saxena (OP); Tom Zanussi, Bruce Ashfield (replies) | Yocto Project mailing list | https://docs.yoctoproject.org/pipermail/yocto/2011-September/002629.html
    candidate_problem: Given a target object, compute the full set of options (including transitive depends/select) required to build it (config-for), and explain why a requested option was dropped.

[145] (pain_point/anecdote, 2017-09-30) Kconfig fragments in Yocto silently fail to reach the final .config, and the audit task does not catch it. 2017 thread: after upgrading to morty the OP's fragments no longer applied; kernel_configcheck did not flag it; the maintainer's first answer was that the cause 'could be either' his recipe or the lower-level class.
    quote: "The kernel_configcheck task doesn't catch the error either."
    source: [yocto] Configuration fragments not making it into kernel configuration | Jonathan Haws (OP); Bruce Ashfield | Yocto Project mailing list | https://docs.yoctoproject.org/pipermail/yocto/2017-October/038236.html
    candidate_problem: Explaining why a requested option or object is absent from a .config/build ('why' command): the chain of unmet dependencies or Makefile conditions.

[146] (policy/policy, 2015-04-04) Yocto maintainer 2015: the kernel Kconfig system overrides fragments; old values or values with missing dependencies are removed during configuration, the tools only warn, and the audit details had only recently become visible in build output. Shows the embedded ecosystem relies on after-the-fact warnings rather than a model of dependencies.
    quote: "the kernel configuration system (i.e. korg, not yocto) has the final say."
    source: [yocto] [kernel config]: specified values did not make it into the kernel's final configuration | Bruce Ashfield (reply) | Yocto Project mailing list | https://docs.yoctoproject.org/pipermail/yocto/2015-April/024392.html
    candidate_problem: Pre-build prediction of which requested options will survive Kconfig resolution and which objects they build.

[206] (policy/tool, 2026 (current docs)) Yocto kernel docs: a config audit task validates that requested fragment options actually appear in the final .config. The audit exists because requested options are silently dropped (dependencies unmet).
    quote: "Running this task produces warnings for when a requested configuration does not appear in the final `.config` file"
    source: Yocto Project Linux Kernel Development Manual, common tasks | Yocto Project | docs.yoctoproject.org | https://docs.yoctoproject.org/kernel-dev/common.html
    candidate_problem: Detecting requested options that silently do not take effect; explaining why an object/option is not built

[207] (pain_point/anecdote, undated (current docs)) ChromeOS kernel config guide: enabling a config without its dependencies makes it vanish, and editing a shared option must be repeated for each flavour (~10) with silent no-op if one is missed.

    source: Kernel Configuration (Chromium OS developer library) | ChromiumOS kernel team | chromium.org | https://www.chromium.org/chromium-os/developer-library/guides/kernel/kernel-configuration/
